# Access tiers

Define who may see which digital assets. Implement in Google Drive sharing, Sheet protection, and Workspace admin roles — not on the public website.

Officer titles: **Host** (President), **Clerk** (Secretary), **Yeoman** (Marshal), **Franklin** (Treasurer).

## Tier A — Host and Franklin

Sensitive personal information:

- Membership contact details held as sensitive
- Health / medical disclosures
- Insurance records and policy references
- Exports for insurers or regulators when required

Both roles should hold access so absence of one person does not lock the association out.

## Tier B — Yeoman / Marshalate

- Marshal’s Log and weapon/armour inspection ledgers (retain ≥ 7 years where policy requires)
- Event Conclave / post-fight minutes
- Kit history reviews for combat clearance
- Field incident templates (full medical narrative stays Tier A where required)

## Tier C — Chapter (Host, Clerk, Yeoman, Franklin, and other elected officers)

- Membership Sheet columns that are not Tier A
- Operational Records (non–Tier A)
- Public Assets (logos, press photos, heraldry files)
- Website repository write access (or PR approval)
- Workspace admin as assigned (prefer Franklin + Host)

## Tier D — All members in good standing

- Research Library / Historical Library (view; optionally comment)
- Private member hub
- Public website and public social channels

## Tier E — Public

- This GitHub Pages site
- Public social media
- Published foundational documents marked as drafts until adopted

## Rules of thumb

1. **No Tier A data in git, Discord, or public social.**
2. **Personal Google accounts are not the system of record.**
3. On leaving office, remove elevated sharing the same week.
4. Review sharing quarterly (Franklin owns the calendar reminder).
