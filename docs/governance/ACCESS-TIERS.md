# Access tiers

Define who may see which digital assets. Implement these rules in Google Drive sharing, Sheet column protection, and Workspace admin roles — not in the public website.

## Tier A — Prior and Armorum

- Membership columns marked **restricted** (health notes, insurance policy numbers, medical alerts)
- Incident reports and related Operational Records subfolders
- Ability to export membership data for insurers or regulators when required

Both roles should hold access so absence of one person does not lock the association out.

## Tier B — Committee (Prior, Armorum, Arca, and other elected officers)

- Full Membership Sheet except Tier A columns (unless also Tier A)
- Operational Records: marshal logs, conclave responses, insurance certificates, templates
- Public Assets folder (logos, press photos)
- Website repository write access (or PR approval rights)
- Workspace user management as assigned (prefer Arca + Prior as admins)

## Tier C — All members in good standing

- Research Library (view; optionally comment)
- Private member hub (announcements and discussion)
- Public website and public social channels

## Tier D — Public

- This GitHub Pages site
- Public social media (education, events, recruitment)

## Rules of thumb

1. **No Tier A data in git, Discord, or public social.**
2. **Personal Google accounts are not the system of record** for association files.
3. When someone leaves office, remove their elevated sharing the same week; do not wait for AGM paperwork alone.
4. Review sharing quarterly (Arca owns the calendar reminder).
